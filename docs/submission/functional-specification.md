## 2. 서비스 목적과 범위

사용자가 설명한 금융사기 의심 상황에서 확인된 행동을 구조화하고, 복수의 피해 노출 상태와
공식 대응 행동을 우선순위대로 안내한다. 서비스는 금융사기 여부를 확정하거나 금융회사·수사
기관을 대체하지 않는다.

### MVP 포함 범위

- 로그인 없는 공개 웹서비스
- 자유 입력과 7개 샘플 시나리오
- 외부 전송 전 민감정보 로컬 마스킹
- 행동 상태 구조화 및 추가 확인
- 7개 다차원 노출 축과 대표 LEVEL 0~5
- 공식 출처 기반 행동지침 조합
- API 미연결·장애 시 로컬 fallback과 고정 긴급안내

### 제외 범위

- 계정, 사용자 이력과 원문 저장
- 자동 지급정지·신고·오픈뱅킹 연동
- 실시간 통화 분석과 기기 직접 제어
- 사기 확률, 법률 판단 또는 안전 확정
- 자체 대규모 모델 학습

## 3. 공통 데이터 정의

### 3.1 추적 행동

| 행동 키 | 의미 |
|---|---|
| `suspicious_contact_received` | 의심 연락 수신 |
| `link_clicked` | 링크 클릭·사이트 접속 |
| `app_installed` | 상대방 안내 앱 설치 |
| `remote_control_enabled` | 화면 공유·원격제어 허용 |
| `personal_info_shared` | 개인정보·신분증 정보 제공 |
| `financial_info_shared` | 계좌·카드 등 금융정보 제공 |
| `auth_secret_shared` | 비밀번호·인증번호·인증수단 제공 |
| `money_transferred` | 송금·현금·상품권 전달 |

### 3.2 행동 상태

| 상태 | 판정 기준 | 질문 정책 |
|---|---|---|
| `done` | 사용자가 수행했다고 명시 | 질문하지 않음 |
| `denied` | 사용자가 수행하지 않았다고 명시 | 질문하지 않음 |
| `requested` | 상대방 요구는 있으나 수행 여부 불명 | 필요 시 질문 |
| `unknown` | 수행 행동을 언급했으나 기억·모순 등으로 불확실 | 질문 |
| `not_mentioned` | 해당 사용자 수행 행동에 대한 진술 없음 | 질문하지 않음 |

민감정보 명사가 등장했다는 이유만으로 `*_shared`를 생성하지 않는다. 문자에 계좌·전화번호가
적혀 있거나 상대방이 정보를 이미 알고 있다는 진술은 `not_mentioned`로 유지하되 맥락을
evidence에 보존한다.

### 3.3 노출 축과 대표 LEVEL

| LEVEL | 노출 축 | 대표 조건 |
|---:|---|---|
| 0 | 없음 | 확인된 위험 행동 부족, 안전을 의미하지 않음 |
| 1 | contact | 의심 연락·요구만 확인 |
| 2 | web | 링크 클릭·사이트 접속 |
| 3 | device | 앱 설치·화면 공유·원격제어 |
| 4 | personal_data / financial_data / authentication | 개인정보·금융정보·인증정보 제공 |
| 5 | financial_loss | 송금·현금·상품권 전달 |

대표 LEVEL은 화면 요약에만 사용하며 행동지침은 활성화된 모든 노출 축으로 결정한다.

## 4. 화면 구성

| 화면 | 주요 요소 | 완료 조건 |
|---|---|---|
| 입력 화면 | 고정 긴급안내, 서비스 설명, 샘플 선택, 텍스트 입력, 분석 버튼 | 로그인 없이 입력·분석 가능 |
| 추가 확인 | 최대 3개 질문, 예·아니오·잘 모르겠음·해당 없음, 결과 업데이트 버튼 | 모든 질문 응답 후 상태 병합 및 질문 영역 종료 |
| 결과 화면 | 지금 즉시 할 일, 복합 노출, LEVEL, 상태 카드, 다음 행동, 증거 보존, 공식 출처 | 모든 done 노출의 필수 지침을 중복 없이 표시 |

색상 의미는 빨강=즉시 행동, 노랑=주의, 파랑=안내로 유지하며 텍스트·아이콘을 함께 사용한다.

## 5. 상세 기능

### F01. 고정 긴급 안내

| 항목 | 명세 |
|---|---|
| 입력 | 없음 |
| 처리 | 분석기·API와 독립적으로 첫 화면 상단에 렌더링 |
| 출력 | 송금 시 금융회사·112 신고, 의심 앱 설치 기기 사용 중단, 민감정보 입력 금지 |
| 예외 | 분석 실패·빈 입력 상태에서도 계속 표시 |
| 검증 | UI 렌더링 및 fallback 테스트 |

### F02. 상황 입력

| 항목 | 명세 |
|---|---|
| 입력 | 최대 3,000자의 자유 입력 또는 7개 샘플 |
| 처리 | 빈 입력 검증, 샘플 선택 시 사전 정의 분석 사용 |
| 출력 | 분석 요청 또는 입력 안내 |
| 예외 | 빈 입력은 외부 추출기를 호출하지 않고 안전 fallback 반환 |
| 화면명 | `예시 상황`, `의심되는 상황을 설명해주세요`, `상황 분석하기` |

### F03. 민감정보 마스킹

| 항목 | 명세 |
|---|---|
| 대상 | 주민등록번호, 전화번호, 이메일, 카드번호, 계좌번호, 인증번호, 비밀번호 |
| 처리 | 외부 추출기 호출 전에 로컬 정규식·문맥 규칙으로 자리표시자 치환 |
| 보존 | 날짜, 시간, 금액, 사건번호, 주문번호 등 사건 판단 정보 |
| 출력 | 실제 값 대신 감지 유형과 외부 전송 전 마스킹 완료 안내 |
| 예외 | 탐지 완전성을 보장하지 않으므로 입력 전 민감정보 작성 금지 안내 유지 |
| 저장 | 사용자 원문과 마스킹 결과를 DB·파일·애플리케이션 로그에 저장하지 않음 |

### F04. 구조화 추출

| 항목 | 명세 |
|---|---|
| 입력 | 마스킹된 텍스트 |
| 처리 | 주체 → 행동 → 수행 여부 → 시간 → 모순 순으로 8개 행동 상태 추출 |
| 출력 | 기관, 위험 신호, 행동별 상태와 evidence를 포함한 검증 객체 |
| 검증 | 허용 필드·상태·타입을 스키마로 검사, 최대 2회 시도 |
| 현재 배포 | `OPENAI_API_KEY` 미설정, `LocalKoreanRuleExtractor` 사용 |
| 선택 경로 | 키가 있으면 구조화 LLM 추출, 실패하면 로컬 분석으로 전환 |

제3자 행동은 사용자 노출로 올리지 않는다. 과거·현재 사건이 함께 있으면 현재 사건의 명시
상태를 우선한다. 행동의 상충 진술은 명확한 최종 정정이 없는 경우 `unknown`으로 유지한다.

### F05. 추가 확인

| 항목 | 명세 |
|---|---|
| 발생 조건 | `requested`, `unknown`, 정규화된 모순 상태 |
| 제외 조건 | `done`, `denied`, `not_mentioned` |
| 질문 수 | 위험 우선순위에 따라 최대 3개 |
| 선택지 | 예, 아니오, 잘 모르겠음, 해당 없음 |
| 처리 | 답변 상태를 기존 분석에 병합하고 노출·LEVEL·지침 전체 재계산 |
| 완료 UI | 선택지 제거, 반영 완료 메시지, 질문·답변 요약 유지 |

### F06. 다차원·복합 판단

| 항목 | 명세 |
|---|---|
| 입력 | `done`으로 확인된 모든 행동 |
| 처리 | contact, web, device, personal_data, financial_data, authentication, financial_loss에 매핑 |
| 복합 기준 | contact를 제외한 실질 피해 영역이 2개 이상 |
| 출력 | 활성 영역 집합, 복합 노출 요약, 대표 LEVEL |
| 중요 원칙 | 대표 LEVEL이 낮은 축의 행동지침을 제거하지 않음 |

### F07. 대표 LEVEL

가장 높은 활성 노출에 따라 LEVEL 0~5를 결정한다. LEVEL 0은 안전 판정이 아니며 확인된
피해 행동이 없거나 정보가 부족하다는 설명과 공식 확인 필요성을 함께 표시한다.

### F08. 공식 행동지침 조합

| 우선순위 | 화면 영역 | 예시 |
|---|---|---|
| `IMMEDIATE` | 지금 즉시 할 일 | 연락 중단, 지급정지·112 신고, 악성 앱 점검 |
| `NEXT` | 다음 행동 | 인증수단 폐기·재발급 확인, 개인정보 노출 등록, 118 상담 |
| `EVIDENCE` | 증거 보존 | 이체내역·문자·대화·연락처 보존 |

활성 행동에 해당하는 모든 지침을 조회하고 `action_id` 기준으로 중복 제거한다. 지침은 LLM이
작성하지 않으며 `data/response_guides.json`의 공식 근거만 사용한다.

### F09. 결과·근거·출처

결과 표시 순서는 다음과 같다.

1. 지금 즉시 할 일
2. 복합 노출 요약과 현재 노출 상태
3. 대표 피해 단계
4. 입력·추가 확인 근거
5. 다음 행동과 증거 보존
6. 기관명·자료명·URL·확인일

### F10. 샘플 시연

| 샘플 | 기대 LEVEL |
|---|---:|
| 의심 문자만 수신 | 1 |
| 택배 문자 링크 클릭 | 2 |
| 검찰 사칭 앱 설치 | 3 |
| 개인정보·계좌정보 전달 | 4 |
| 안전계좌 송금 | 5 |
| 앱 설치 여부 불명확 | 1 + 추가 질문 |
| 앱·인증번호·송금 복합 피해 | 5 |

### F11. 장애 대응

| 조건 | 동작 |
|---|---|
| API 키 없음 | 로컬 규칙 분석 사용 및 방식 고지 |
| 공급자 오류·timeout | 최대 시도 후 로컬 분석으로 전환 |
| 잘못된 JSON·스키마 | 결과 거부·재시도 후 로컬 분석으로 전환 |
| 빈 입력 | 공급자를 호출하지 않고 입력 안내 |
| 모든 경우 | 고정 긴급안내와 공식 확인 경로 유지 |

실측값이며 LLM 성능으로 표현하지 않는다.
