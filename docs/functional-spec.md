# MVP 기능명세서

## 서비스 목적

금융사기 여부를 확정하지 않고 사용자가 설명한 상황에서 확인된 피해 노출과 즉시 대응 행동을 안내한다.

## 기능 목록

| ID | 기능 | 입력 | 처리 | 출력·예외 |
|---|---|---|---|---|
| F01 | 고정 긴급 안내 | 없음 | AI와 독립적으로 표시 | 송금·악성 앱 긴급 행동 |
| F02 | 상황 입력 | 최대 3,000자 | 빈 입력 검증 | 분석 요청 또는 안전 안내 |
| F03 | 민감정보 마스킹 | 사용자 원문 | 외부 전송 전 로컬 치환 | 마스킹된 텍스트만 전달·감지 유형 안내 |
| F04 | 하이브리드 구조화 추출 | 마스킹된 텍스트 | LLM 우선·로컬 규칙 fallback | 복수 행동의 검증된 상태 |
| F05 | 추가 질문 | requested·unknown 상태 | 최대 3개 질문 확인·명시 응답 병합 | 답변 요약·미확인 상태 유지 |
| F06 | 다차원·복합 판단 | 확인된 done 상태 | 7개 노출 축 보존·합성 | 복합 노출 요약과 상태 집합 |
| F07 | 대표 단계 | 다차원 상태 | 규칙 기반 LEVEL 0~5 | 사용자용 요약 단계 |
| F08 | 행동 조합 | 모든 노출 상태 | 공식 지침 조회·정렬 | 즉시·다음·증거 보존 |
| F09 | 근거 표시 | 분석·지침 메타데이터 | 중복 출처 제거 | 위험 신호·공식 출처·확인일 |
| F10 | 샘플 시연 | 7개 사전 정의 사례 | 동일 규칙 파이프라인 실행 | 기대 단계·행동 |
| F11 | 장애 대응 | API·파싱·입력 오류 | 최대 2회 시도 후 로컬 분석 전환 | 분석 방식 고지·고정 안전 안내 유지 |

## 비기능 요구사항

- 로그인 없이 공개 URL에서 실행한다.
- 사용자 원문과 결과를 DB에 저장하지 않는다.
- 비밀키를 저장소에 커밋하지 않는다.
- 행동 지침은 LLM이 생성하지 않는다.
- 색상만으로 위험 수준을 표현하지 않는다.
- 공식 지침은 배포 전 URL과 최신성을 재확인한다.

## 환경 변수

| 이름 | 필수 여부 | 설명 |
|---|---|---|
| `OPENAI_API_KEY` | 선택 | 설정 시 LLM 구조화 추출에 사용 |
| `OPENAI_MODEL` | 선택 | 기본값 `gpt-5.6-luna`, 배포별 모델 재정의 |

키가 없을 때는 로컬 규칙 추출기가 주요 표현의 자유 입력을 처리한다. 로컬 규칙 범위를 벗어난 문장은 미확인 상태로 유지하며, 샘플 시연과 고정 긴급 안내는 항상 정상 작동한다.

현재 배포는 Streamlit secret의 API 키로 OpenAI Responses API Structured Outputs를
우선 사용한다. 마스킹된 입력만 전송하고 응답 저장은 비활성화하며, SDK 재시도를 끈 상태로
애플리케이션에서 최대 2회 시도한다. 실제 LLM 50건 평가는 아직 실행하지 않았으므로 제출
자료에는 LLM 성능 수치를 기재하지 않으며, 완료된 로컬 분석기 회귀 결과와 마스킹 평가만
명시한다. 키 누락, 시간 초과, 공급자 오류 또는 스키마 검증 실패 시 로컬 분석으로 전환하고
고정 긴급안내와 공식 확인 경로를 유지한다.

## 현재 구현 상태 (2026-08-24)

- 추가 확인은 미응답을 검증하고 `예`·`아니오` 응답을 기존 상태에 병합한 뒤 결과 전체를 다시 계산한다.
- 추가 질문은 `requested`·`unknown` 상태에만 표시하며 `done`·`denied`·`not_mentioned`에는 표시하지 않는다. 중요 피해 행동의 상충 진술은 마지막 표현을 임의로 채택하지 않고 `unknown`으로 정규화해 재확인한다.
- MVP의 상위 행동 축에 여러 세부 정보의 제공·미제공이 섞이면 하나라도 제공된 노출 축은 `done`으로 판정하되, 서로 다른 세부 사실을 `evidence`에 각각 보존한다.
- `잘 모르겠음`은 미확인 상태로 유지하되 현재 분석에서는 답변 완료로 처리해 같은 질문을 반복하지 않는다.
- 추가 확인 결과는 `개인정보 전달 여부: 아니오`처럼 결과 화면에 판단 근거로 유지한다.
- 상태 카드는 `확인됨`·`사용자가 아니오로 확인`·`추가 확인 필요`·`언급 없음`을 구분한다.
- LEVEL 0은 확인된 피해 행동, 부정·불확실 상태와 민감정보 마스킹 여부를 이용해 산정 이유를 설명한다.
- 민감정보가 감지되면 원문 값을 노출하지 않고 로컬 마스킹 완료 유형을 화면에 알린다.
- 앱 설치·개인정보 제공·송금처럼 여러 행동이 함께 있으면 자연어에서 각 상태를 독립적으로 추출·보존한다.
- API 키가 없거나 LLM 연결이 실패해도 핵심 행동은 로컬 규칙으로 분석하고 분석 방식을 고지한다.
- 복합 피해는 실질 피해 영역을 카드로 표시하고 모든 영역의 공식 지침을 합쳐 정렬한다.
- 단순 상황 6개와 `앱 설치·인증정보 전달·송금` 대표 복합 피해 1개, 총 7개 샘플을 제공한다.
- 규칙·지침·자연어 추출·평가 데이터·전후 비교·문맥 회귀·안전 흐름·UI 보조 로직 자동 테스트 86개가 통과한다.
- 프롬프트 인젝션성 문장이 앱 설치·송금과 함께 있어도 두 피해 행동과 LEVEL 5 지침을 보존하는 회귀 테스트가 통과한다.
- 주체·시간·요구/거절·구어체·정정·가정·사후 조치·부분 제공 문맥 CASE 1~50을 별도 피드백 데이터와 회귀 테스트로 관리한다.
- 전체 `src` 테스트 커버리지는 90%, 로컬 자연어 추출기 커버리지는 100%다.
- 실제 LLM 자연어 판정 성능은 API 연결 후 별도 평가 세트로 측정해야 한다.

### 제출 기준 평가 스냅샷

- 기존 범주형 자연어 평가 45건은 초기 취약 유형 확인용 baseline이다.
- 피드백 반영 후 별도로 구축한 제출용 문맥 회귀 50건은 로컬 분석기에서 50/50 통과했다.
- 합성 마스킹 70건과 은행 계좌번호 문맥 63건을 합친 통합 마스킹 133건은 133/133 통과했다.
- 행동지침 독립 라벨은 필수 33개 누락 0건, 금지 48개 발생 0건이다.
- 초기 45건과 제출용 50건은 데이터셋과 라벨 범위가 다르므로 직접 향상률로 표현하지 않는다.
- 실제 LLM 50건 평가는 실행하지 않았으며 로컬 지표와 섞어 쓰지 않는다.
